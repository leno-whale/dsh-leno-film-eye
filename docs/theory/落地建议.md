## 二、落地前必须写死的三件事（操作定义）

### 1. $e^*$ 怎么匹配

定理 1 的两参数模型要求「同样倾向、不同延迟」。落地时必须能说清楚：**这一次的 $e^*$ 和那一次的 $e^*$ 是同一个结果类别**。

- 对游戏/影视素材：$e^*$ 可以是「某个动机解决」「某个镜头切回」「某个角色出场」。需要一条**对象匹配规则**（按标签、按时间邻域、或按特征聚类）。
- 这条规则不写死，$\rho_{\rm care}(e)$、$q_1(e)$、$n(e)$ 全部无法数。

### 2. $b_1$ 的日志事件

定义 4 说 $b_1=\mathbb 1[\text{行为反应被阻止}]$。落地需要一个**具体的日志事件**：什么算「行为被阻止」？是任务切换被取消、输入被忽略、还是某个动作没执行？账房里得有这一行。没有它，定理 1 的 $b_1b_2$ 因子永远乘不上去。

### 3. $q_1(e)$ 的「转向 $e$ 相关对象」

§12.4(e) 的 $q_1(e)$ 是「当前行为被中断、转向 $e$ 相关对象的比例」。这里「相关对象」的判定规则必须写死——按对象 ID 精确匹配、按类别匹配、还是按时间窗内共现。这条不写死，$\hat\rho_{\rm care}$ 数不出来。

## 三、$\lambda$ 实验的最小设计（最该先跑的）

文档说「三点即可定」，**实操上至少 5 个不同 $\Delta$**，否则 `curve_fit` 的协方差矩阵退化，$\hat\lambda$ 没有标准误。最小设计：

1. 固定一个 $e^*$ 类别，收集 **≥5 个不同兑现延迟 $\Delta_k$** 的片段；
2. 每个片段满足 $p_t$ 近似常值（或至少记录 $p_t$ 轨迹，事后数值积分对照）；
3. $y_k$ 用 $\mathcal I$ 的行为代理（§12 表），**不要用 $T_t$**——$T_t=\kappa'V_tb_1$ 是累积势的即时读数，不含折扣，估的是 $V$ 的形状，不是 $\lambda$；
4. 拟合 $\mathcal I(\Delta)=c(1-e^{-\lambda\Delta})$，先共享 $\lambda$、允许每个 $e^*$ 子组有自己的 $c_k$——这样 $\rho_{\rm care}$ 的绝对尺度被 $c_k$ 吸收，**即使 $\rho_{\rm care}$ 只保序，$\lambda$ 仍可估**。这是 v2.1 拆分后最重要的落地红利，文档没明说，但成立。

## 四、一个会卡住的现实问题：$b_2$ 太严，$\mathcal I$ 大量为零

定理 1 要求 $b_1=b_2=1$ 才非零。$b_2$ 的代理是「1 小时内改写同一对象 ≥2 次」，这个门槛很高，很多片段会直接掉到 $\mathcal I=0$，导致 $y_k$ 一堆零，拟合没有曲率信息。

落地建议（不改理论，只改用法）：

- **先用 $b_1=1$ 筛样本**，把 $b_2$ 当连续代理而不是 0/1——比如用改写次数 $n(e)$ 的归一化值乘进去，作为 $b_2$ 的软版本；
- 或者**先用 $T_t$ 的窗内斜率做 $V/p_t$ 的形状检验**（这部分不依赖 $b_2$），确认 $p_t$ 的 Laplace 估计方向对，再上 $\mathcal I$ 估 $\lambda$。

这不算改公理，是把 $b_2$ 的 0/1 硬化放松成可拟合的连续量——文档 §12.4(b) 已经说「必须与 $f$ 联合判读」，顺着这个走就行。

## 五、工具链：待估参数 → 现成工具的映射

| 文档里的待估项 | 对应工具 | 它能做到哪一步 |
|---|---|---|
| $p_t$（重复次数 $n_t$） | `librosa.segment.recurrence_matrix` / MUSION `struct` | 从音频直接数重复动机、检测结构边界 |
| F0、能量、jitter、shimmer | `openSMILE` eGeMAPS / `librosa.pyin` / `CREPE` | 算 §1.1 的 $z_t$ 特征 |
| $\lambda$ 与 $c$ | `scipy.optimize.curve_fit` | 直接拟合 $\mathcal I(\Delta)=c(1-e^{-\lambda\Delta})$ |
| $\rho_{\rm tol}$（压缩容差） | `ffmpeg` + 任意特征提取器 | 做 §12.4(c) 的压缩对比实验 |
| $\mathrm{conf}$ 的 Hellinger 距离 | 现成 Python 函数（几行） | 层间分布比较 |
| $b_1$ 行为阻断 | 自己的日志/账房数据 | 工具帮不上，但数据源已经在 |

### 5.1 $p_t$：数重复是最需要的，也最有工具支撑

§12.4(a) 的 $\hat p_t=(n_t+1)/(n_t+2)$ 核心操作是**数「当前模式重复了几次」**，不需要标注，但需要工具把重复片段检测出来。

- **`librosa.segment.recurrence_matrix`**：从特征矩阵算自相似矩阵，对角线平行的亮条纹对应重复片段；配合 `segment` 模块的 `agglomerative` 等分割函数切段，段与段的重复关系就是 $n_t$ 的来源。
- **MUSION 的 `struct` 模块**更省事：输入音频路径直接输出结构分段，对流行歌能检测副歌，不用自己调自相似矩阵。

工具能给 $n_t$，但**不能替验证 $n_t$ 是不是「我的期待」**——§13 那个最大洞只能靠实测延续率与 Laplace 估计对照来检验。

### 5.2 F0 与声学特征：eGeMAPS 是现成的标准路径

§1.1 的 $z_t$ 需要基频、能量、频谱特征，命题 6/7 涉及「有没有 F0」。**openSMILE 的 eGeMAPS 特征集**是语音情绪领域最常用的最小声学参数集：

```python
import opensmile
smile = opensmile.Smile(
    feature_set=opensmile.FeatureSet.eGeMAPSv02,
    feature_level=opensmile.FeatureLevel.Functionals,
)
df = smile.process_file("audio.wav")
```

eGeMAPS 直接输出 pitch、jitter、shimmer、HNR、loudness。命题 6 在实操上就是：**如果 eGeMAPS 的 pitch 列不可用或置信度低，那段就不能声称能区分「沉」**。

只要 F0 且想比 pYIN 更稳，用 **CREPE**：`python -m crepe audio.wav` 输出时间戳 + F0(Hz) + voicing confidence 的 CSV，默认 10 ms hop，与 §1.1 的 $\Delta=0.025$ s 帧长兼容。

### 5.3 $\lambda$ 与 $c$：`scipy.optimize.curve_fit` 就是给这个式子写的

```python
from scipy.optimize import curve_fit
import numpy as np

def I_model(Delta, c, lam):
    return c * (1 - np.exp(-lam * Delta))

# Delta: 不同延迟；y: 实测强度（行为代理）
popt, pcov = curve_fit(I_model, Delta, y, p0=[1.0, 0.1], bounds=(0, np.inf))
c_hat, lam_hat = popt
perr = np.sqrt(np.diag(pcov))  # c 和 lambda 的标准误
```

`pcov` 对角线给参数方差。注意三点拟合会恰好穿过三点、残差为零、`pcov` 退化——**至少 5 个不同 $\Delta$，标准误才有意义**（见 §三）。`bounds=(0, np.inf)` 把参数限制在正数域。

**诚实提醒**：`curve_fit` 能估 $\lambda$，但不能替制造「不同延迟的强度数据」——§12 表里 $\mathcal I$ 的代理量 $y_k$ 的构造仍是自己的操作化。

### 5.4 $\rho_{\rm tol}$：全文最容易当场执行的实验

```bash
ffmpeg -i original.wav -b:a 128k compressed.mp3
```

用 openSMILE 或 librosa 分别提取原始与压缩后的同一套特征，按 §12.4(c) 的式子算 $\sup|f(x)-f(D(x))|/\max(|f(x)|,\epsilon)$，取 $1-$ 该值即 $\hat\rho_{\rm tol}$。文档里「我手上有 ffmpeg」的说法完全正确，**没有任何工具缺口**。

### 5.5 $\mathrm{conf}$ 的 Hellinger：离散/连续要分开

离散分布的现成实现：

```python
def hellinger_distance(L1, L2):
    H = sum((x**0.5 - y**0.5)**2 for x, y in zip(L1, L2))
    return (1 / (2**0.5)) * (H**0.5)
```

要求两分布定义在**同一离散支撑集**上且归一化。三套编码里 `Discrete_7`、`GEMS_9` 可直接用；`[-1,1]×[0,1]` 工程编码是连续的，**须先分箱**（或改用对密度积分的连续版本）。依公理 E1 与 A7，$\mathrm{conf}$ 只在同一 $\mathcal Y$、同一口径标签 $\ell$ 内计算。

## 六、工具帮不上的（如实登记）

- **$b_2$ 的本质验证**：「1 小时内改写 ≥2 次」是账房数据的事，声学工具替代不了；
- **$\rho_{\rm care}(e)$ 的数值**：没有现成工具能估「对某个结果有多关切」，只能靠跨片行为数据拟合，或按降级预案只保序——但注意 §三.4 的红利：$c_k$ 吸收尺度后 $\lambda$ 仍可估；
- **$\kappa,\kappa',\alpha,\beta$**：工具能跑回归，但样本只有一部片，工具不制造可识别性。

## 七、还挂着、但不挡路的

- 命题 5 是工作假设——但它直接说明 **4 s 窗只能做序/类别，别做维度回归**，反而简化落地；
- Meyer/Huron 跨文化挪用——落地时把「西方调性」标签挂在结论上即可，不影响 $\lambda$ 的数值估计；

## 八、最小可执行清单（现在就能跑）

1. `pip install opensmile librosa scipy`；
2. 用 openSMILE eGeMAPS 跑手上那部片，得逐帧 $z_t$，确认 pitch 列是否可用（直接决定命题 6/7 的适用范围）；
