### 3.4 本次暴露的三个口径缺陷（记录，不据以重跑改判读）

1. `with_sink` 只判 `|Δ| ≥ 1`，**未判方向** —— 升也算「沉的伴随」，`+22.96` 即被此条误收。
2. `p_with_sink` 的**分母含 `null`**（未定音），把「判不了」当成「没沉」，系统性压低 p。
3. **判读无最小样本量**（第二批访谈片暴露，见 §3.5）—— n=2 也能算出 p=1.0 并判「盲区代价大」，

三处均为实现缺陷，非数据缺陷。修正版须：方向必须为 down；`null` 从分母剔除并单独报
「不可判率」；可判样本 <`MIN_DECIDED`（=20）一律报 `insufficient`。

### 3.7 独立口径 3 dB（作者裁决「另开」）

> **判读先写死**：本节先于结果落地，与代码同一 commit。这是独立实验臂，不是对 §3.6 的重分析。

**为什么另开**：6 dB/4 s 在广播级访谈上几乎不触发——两支 sd=1.4 的成片，85 min 只有 2 个塌、18 min 一个没有；放到 3 dB，四支合计 253 个。继续在 6 dB 上堆素材，等于要求作者去找「电平不合工业规范」的素材。

**判读（逐字沿用，未因换阈值改动）**

1. 事件：4s 窗 db 环比跌 **≥3 dB**（`--drop-db -3`）。
2. 伴随沉：窗中位半音相对上一窗降 **≥1** 且方向 down；$|\Delta_{\rm st}|>12$ 视作八度误判，记不可判。
3. 分母只算可判事件（前后窗均定音），另报 `p_undecidable`。
4. 可判 < `MIN_DECIDED`（20）→ `insufficient`；≥50% → 盲区代价大；<20% → 实际盲区小；中间灰区只报数。
5. **不可比、不可合并**：6 dB 事件必定也是 3 dB 事件，反之不然；两个事件总体不同，p 不相加、不并表。
6. **事件不独立**：连续下坡会被切成多个相邻事件，summary 另报 `n_runs`（连续段数）；区间按 run 算，不按事件算。

**这条不负责把 `insufficient` 变成结论**：若 3 dB 下可判仍 <20，或区间仍跨 0.5，结论照旧是不足。3 dB 只让「事件太稀」不再挡路，不改判读。

**run 级判读（补充写死；此条在结果落地之前写，见 commit 时间）**

相邻窗逐级跌 ≥3 dB 的连续事件合并成一个 run。run 的沉判定用**首尾净变化**：

$$\Delta_{\rm run}=\text{中位半音(run 末窗)}-\text{中位半音(run 首窗的前一窗)} .$$

$\Delta_{\rm run}\le-1$ 且 $|\Delta_{\rm run}|\le12$ 记 sink；两端缺定音或超 12 半音记不可判。
两端窗都在两遍法已经算过的集合里（首事件要它前一窗、末事件要它本窗），**不需要补跑**。

样本量以**可判 run** 计：<20 仍报 `insufficient`；event 级 p 只作描述，不作判读。

**结果（2026-10-31，本机 CPU，pyin，两遍法，`gpu/out-voiceset-3db-2026-10-31/`）**

| 素材 | 时长 | 4s 窗 | 塌事件 | run | 可判事件 | 沉 | 可判 run | 沉 run | run 级 p |
|---|---|---|---|---|---|---|---|---|---|
| 31290560007-1-192 | 26 min | 389 | 34 | 30 | 30 | 20 | 26 | 19 | 0.73 |
| 31785420299-1-192 | 123 min | 1849 | 173 | 168 | 168 | 84 | 163 | 82 | 0.50 |
| 43155328889-1-192 | 85 min | 1276 | 42 | 41 | 31 | 29 | 30 | 28 | 0.93 |
| 央视访谈 | 18 min | 269 | 4 | 4 | 4 | 3 | 4 | 3 | 0.75 |
| **合计** | **4.2 h** | **3783** | **253** | **243** | **233** | **136** | **223** | **132** | **0.59** |

- **判读（按 §3.7 先写死的规则）**：可判 run 223 ≥ 20，p = 132/223 = **0.592**，
  Wilson 95% = **[0.53, 0.65]**，下界 > 0.5 → **「盲区代价大（≥50%）」**。
  event 级只作描述：136/233 = 0.584，Wilson [0.52, 0.65]，与 run 级一致。
- **Φ 的 AUC（6a 口径，记录）**：`T_t^-` 0.447 [0.369, 0.526]、`D` 0.553 [0.477, 0.628]、
  `L_0` 0.458 [0.385, 0.530]；按 $L_0$ 三分层（切点 −23.6 / −21.4 dB）后九个区间**全部含 0.5**。
  按 6a §四.2 的写死判读，落在「完全盲」一格：**本素材、本口径下 Φ 不带 sink 的信息**。
  区间未按片聚类，bootstrap 是 iid 的，宽度偏窄——这只会让「含 0.5」更保守，不会让结论翻向可恢复。

**这一格读数是什么、不是什么（不藏）**

1. **它测的是「响度跌时基频在跌」的频率，不是「带情绪标记的沉」的频率。** 事件总体是 3 dB 小台阶
   （140/233 落在 −3~−4 dB），中文语调的句末下降本来就会同时压低响度与 F0——这正是 §3.6 里
   「什么能打死它」第 4 条（声调污染）。要拆开必须做声调/句末标注，本批没有。所以 0.59 只能读作
   **操作性盲区**的大小，不能读作「沉真的占 59%」。
2. **没有剂量-反应。** 跌幅与 $\Delta_{\rm st}$ 的相关只有 $r=0.065$（n=233），
   沉率在 −3~−4 / −4~−6 / −6~−12 dB 三箱分别是 0.55 / 0.61 / 0.71。
   所以这不是「跌得越狠、音高跟着掉得越多」的简单物理耦合；共现是结构性的，来源尚未分解。
3. **片间异质性大**：run 级 0.50–0.93（一支正好 0.50）。4 支 < 5，按纪律只报 pooled、不给跨片分布；
   Wilson 按 run 算，但片内仍相关，**真实不确定性比区间更宽**。
4. **6 dB 与 3 dB 是两张表**，p 不相加、不合并（先写死的第 5 条）。
5. **阈值是在看到 6 dB 失败之后才开的**，这一点不能洗。能做的都做了：判读逐字沿用、结果分表、
   开跑前把规则写进本节与代码（commit `b87a8a3`），并把本口径特有的混杂摆在这里。
   作者若不接受这个口径，6 dB 侧仍然是 `insufficient`，这条不替它翻案。

**对理论的两句话**

- 6a 侧：本素材未发现可恢复结构（Φ 对 sink 无信息），与命题 6 的「不可识别」一致；
  这是**支持**，不是证明——只有 4 支片，且是 pooled。
- 6b 侧：0.59 不是效应量。按 6b，sink 不进 $I$，这个数只能用来报盲区大小；
  不许由此推出「59% 的塌让情绪更强」。

这是 6a 的测量层，不改任何符号。

**素材与换尺**：批一那 6 支片原用 CREPE，voiced 只有 0.22——若它们真是 MV，这个数不该这么低
（CREPE 在歌唱/乐器上强，对纯说话声才失灵）。所以先用 **pyin 整片**重跑同一批片，两种 meter **分表**，
看 0.22 是素材性质还是尺子问题。

**段分类（先写死，且不看 db、不看 sink）**

- 一个 4s 窗记「有调性」当且仅当 `voiced ≥ 0.5` **且** `f0_iqr ≤ 1.0 半音`（音高稳）。
  依据：说话声的 F0 连续滑动，窗内 IQR 通常更大；乐器/歌唱在窗内有稳定音高。
- 连续 ≥3 个有调性窗（≥12 s）记一个「音乐段」，其余窗记「非音乐段」。
- 分类只由 f0/voiced 决定，**不许用 db 或 sink 去定义分组**（否则读数循环）。

**主读数**：6 dB 塌事件在音乐段 / 非音乐段各自的「塌→沉」共现率；可判 <20 一律 `insufficient`；
两段 p **不相加**；阈值不动（仍是 −6 dB、沉 ≥1 半音、|Δ|>12 判无效）。

**什么能打死它**

1. 有调性窗太少（<60 个）→ 无法分段，判 `insufficient`，并说明「批一素材不是音乐为主」。
2. 音乐段里 6 dB 事件可判 <20 → `insufficient`，只报密度。
3. **分类本身没分开**：若两段的 Δst 中位数差 <1 半音，说明 IQR 阈值没区分出音乐与说话，
   分段读数作废，只报原始分布。
4. pyin 与 CREPE 在同一批片上若给出完全不同的 voiced 结构，只许各自成表，**不许择优**。

**结果（2026-10-31，`gpu/out-mv-pyin-2026-10-31/`，整片 pyin）**

| 片 | CREPE 有声窗/均值 | pyin 有声窗/均值 | pyin 窗内 IQR 中位 |
|---|---|---|---|
| 28871298443 | 31/54 · 0.38 | 54/54 · 0.63 | **8.05** |
| 42911989885 | 10/54 · 0.31 | 52/54 · 0.44 | **9.50** |
| 42980740098 | 4/37 · 0.39 | 37/37 · 0.55 | **10.80** |
| 43068556628 | 22/66 · 0.30 | 66/66 · 0.73 | **9.56** |
| 43115939271 | 2/47 · 0.27 | 47/47 · 0.49 | 1.20 |
| 467586220_da2 | 10/101 · 0.32 | 70/101 · 0.42 | 2.85 |

（均值为「有音高窗」的窗内 voiced 比；两把尺子分表，不比较绝对值。）

**判定：`insufficient`——这批素材做不了音乐侧盲区。**

1. **有调性窗只有 24/359（0.067）**，远低于先写死的 60 → 无法分段（§3.8 第 1 条）。
2. **根因不是尺子，是素材**：pyin 能测到更多有声窗，但四支片的**窗内 IQR 中位 8.0–10.8 半音**——
   4 s 内音高乱跳。干净音乐应 <1 半音，说话声 1–3 半音；8–11 只可能是**对白+配乐+音效的混合声**，
   单音高跟踪器在其上读到的是多声源的拼接，不是旋律。CREPE 干脆判无声，pyin 判到但读数无效。
3. 6 dB 事件的**数目不变**（仍是 20，db 与 F0 无关），pyin 下可判 **10** 条，仍 <20 → 即使不分段也不够。

**所以「MV 片子怎么办」的答案不是理论行不行，而是**：这 6 支片本身不是可用的音乐素材——
它们是混合声，单音高 F0 在其上不成立。要测音乐侧盲区，只有两条路：

- 换**干净音乐段/分轨**（无对白、无音效），单音高 F0 才有效；
- 或换**不依赖单音高 F0 的表示**（chroma / HPSS / 和声特征）——但那就改变了「沉」的定义
  （从 F0 下降变成和声/音级运动），必须另开一条臂、重新写死判读，**不能借这一条的名义**。

这一批的正面价值：它把「MV 能不能用」从一句直觉变成了一个可执行的素材门槛。**不要拿它当
「音乐里盲区小」的证据——一条都没测到。**

### 3.9 MV 试点：人声分离后的 F0（新尺子，单独成表）

> **判读写死，先于结果。** 作者指出：28871298443（红泪石戒指）是中文歌 MV、无对白。
> 所以 §3.8 的「混合声」措辞作废——正确说法是**多声部混音**：单音高跟踪器在全混音上会在
> 人声/贝斯/吉他之间跳，并出八度误判（窗内 IQR 8.05 半音正是这个症状），不是素材没有音乐。

**尺子**：`meter: demucs+pyin` = htdemucs 分离 vocals 轨 → pyin。
fmin 65 / **fmax 1000**（歌唱音域；说话用的 500 不够，女声高音会被削）。与前面两把尺子**分开成表**。

**不变的部分**：4 s 窗、db 8k/20log10、塌 −6 dB、沉 = 降 ≥1 半音且 $|\Delta_{\rm st}|\le12$、
前后窗定音才算可判、`MIN_DECIDED=20`。一个都没改。

**试点的主终点是「尺子能不能用」，不是 p**

| 读数 | 判读 |
|---|---|
| 分离后 voiced 窗内 IQR 中位 **≤2 半音**，且 voiced 均值 ≥0.6 | 尺子成立，可以扩到 6 支 MV |
| IQR **2–3 半音** | 部分成立，只作探索 |
| IQR **>3 半音** | 尺子不成立，MV 路线要换前端（melodia / chroma），不许拿它出数 |

**次读数**：该片 6 dB 事件只有 3 个（db 与前端无关），可判怎么都 <20 → p 只作描述，
判 `insufficient`。试点**不许**用这一支的 p 讲盲区大小。

**什么能打死它**

1. 分离后 IQR 仍 >3：单音高在复调伴奏上仍然跳，这条路走不通。
2. 分离把主唱也削掉（voiced <0.3）：说明分轨失败，不是尺子问题。
3. **靠换 fmax 才达标**：那是调参凑数，不许；fmax=1000 是开跑前按歌唱音域定的。
4. 把 `demucs+pyin` 的数与 `pyin`/`crepe` 的放进同一张表：不许（A7）。

**结果（2026-10-31，htdemucs CPU 1:45，`gpu/out-mv-demucs-2026-10-31/`）**

| 读数 | 混音 pyin | **demucs+pyin** |
|---|---|---|
| 有音高窗 | 54/54 | 54/54（52 个有 F0） |
| 窗内 voiced 均值 | 0.63 | **0.86** |
| 窗内 IQR 中位 | 8.05 半音 | **4.95 半音** |
| 6 dB 事件 / 可判 | 3 / 1 | 3 / **0** |

**按先写死的判读：不达标（4.95 > 3）。但这次否掉的是我的判据，不是这条前端。**

IQR≤2 这个门槛是我按「单音高是否锁在一条线上」定的，可 4 s 窗里唱歌本来就是 3–7 半音的旋律跨度——
**IQR 量的是窗内音域，不是声源纯度**。分离确实起了作用：voiced 0.63→0.86，IQR 8.05→4.95。
所以正确记录是：**判据被证伪（写死时没分清「复调」和「音域宽」）**，而不是 demucs 路线死。

**另外两个真问题，这次才看见**

1. 三个 6 dB 事件全部不可判。其中 `t=204→208` 的 $\Delta_{\rm st}=+24.1$ 半音（−30.9 → −6.8），
   是**八度/换声区跳变**，按 |Δ|>12 判无效；残留的低频串音还在，分离后单音高仍需八度校正。
2. 三个跌幅是 −8.9 / −26.8 / −27.6 dB，后两个接近整段掉底——**歌里的「塌」多是编曲变化或人声休止**，
   不是说话里那种语气骤降。「塌」这个事件定义本身要按音乐重新想（是混音级掉底，还是人声句内的力度跌）。

**结论**：MV 路线没死，但这次只证明了「分离能明显改善」，没证明「尺子可用于出数」。
下一步若要继续，必须先**另外预注册**一个真正检验声源纯度的指标（如八度跳变率、跨窗 F0 一致性），
不能用这次的 IQR 事后改口。**该片 p 不报**（0 条可判）。

### 3.10 3 dB 事件的语调拆分（分层，不改主读数）

> **判读写死，先于结果。** 只回答一个问题：0.592 里有多少是句间/换气处的自然下降。

**规则**

- 停顿检测：`ffmpeg silencedetect`，`noise=-40 dB`、`d=0.3 s`（默认值，不调）。
- 每个事件（跌后窗起点 $t$）若在 $[t-1,\,t+1]$ 内与某段静音相交 → **跨句跌**；否则 → **句内跌**。
- 其余一律不动：沉 = 降 ≥1 半音且方向 down、$|\Delta_{\rm st}|>12$ 判无效、可判定义、p 与 Wilson、
  **按 run 聚类的 bootstrap**（1000 次，事件嵌在 run 里，不独立）。
- run 的层按其**首个事件**的 $t$ 判定（一个 run 只归一层，不拆）。
- 两层 p **不合并、不改主读数**（§3.7 的 0.592 照旧）。

**判读**

| 情形 | 判读 |
|---|---|
| 两层可判 run 均 ≥20，且差值 95% CI **不含 0**、跨句更高 | 0.59 主要由非表达性下降驱动，3 dB 读数降级为「操作性盲区」 |
| 差值 95% CI **含 0** | 不能说语调解释了它；0.59 可以留着，但仍然只是共现 |
| 任一层可判 run <20 | `insufficient`，只报数 |
| 跨句事件占比 <20% | 分层没意义，判据不成立，只报原始分布 |

**什么能打死它**：停顿检测在这批素材上几乎不触发（<20% 事件跨句）；或两层沉率差 <10 个百分点
——那说明「语调解释」不成立，得另找原因（换气、编曲、限幅），不许硬套。

## 五、复现

bundle 在 `gpu/`（runbook 逐行可粘贴）；素材上传不走 B 站（-412 风险维持 P1 不变），全部从本机传。

本次云端环境的三个坑，复现时会再遇到：

1. base 的 `site-packages` 是**只读挂载**，装不了包 —— 必须 `python3 -m venv /root/venv` 自建环境。
2. 镜像用 `PIP_CONSTRAINT=/etc/pip/constraint.txt` 锁死 `torch==2.7.0a0+...nv25.3`，公开源没有该版本
   → 冲突。用 `PIP_CONSTRAINT= pip install ...` 临时解锁（只作用于单条命令，不改镜像配置）。
3. 镜像自带的 `python3` 是 mambaforge base，与 venv 混用会装错地方 —— 全程用绝对路径
   `/root/venv/bin/python3`。

## 六、什么能打死它（照抄纪律）

1. **域偏移**：情绪模型训练分布是西方流行乐（MTG-Jamendo/MSD 系），中文 MV/BGM 上
   sanity 门不过即作废——不调参救。
2. **CREPE 对纯配乐段失效**：它是人声训练的 pitch tracker；无人声段 F0 读数标 `voiced`
   低信度，判读时只看 voiced ≥0.3 的窗。
3. **塌阈值 6 dB 是先写的**：换阈值会动 p——不许跑完再挑阈值。
4. 单素材不外推；跨片 ≥5 才给分布，否则只标「首跑」。

5. **素材语音密度是硬门槛（本次实测打死它的就是这条）**：6 支片定音率 0.27–0.39，
   合计 0.22（79/359 窗），探针先天不适用，不是理论问题。重做前先算 `voiced_mean`：
   **> 0.6 才开跑**；达不到就换素材（人声密集的对白/演唱片段），
   **不许下调 `VOICED_CONF`（0.5）去凑** —— 那是调参硬凑。
