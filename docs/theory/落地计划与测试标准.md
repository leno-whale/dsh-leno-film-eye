# 落地计划与测试标准

> 写于 2026-10-30。理论正文见 [倾向阻断论](倾向阻断论.md)（v2.1.1）。
> 本文只写**怎么做**和**怎样算通过**——不重复理论。
>
> 第二节是「怎样算通过」，**第七节是「怎么算」**（输入字段、算法、参数、输出、失败模式）。

---

## 〇、目标

把《倾向阻断论》里能算的部分变成每天可复现的数，并用预先写死的标准判断它有没有用。

**不做**：不做论文、不做新插件雏形、不发明新符号。理论里算不了的（音高通道、人际一致性、真正"当真"）在计划里一律显式标"无数据"，不给近似值。

---

## 一、纪律（四条，写死在前面）

1. **口径先行**：每个数必须同时报出「尺子／窗长／门限／样本量」；跨口径的数不并列、不相加、不比较。
2. **先写标准再跑**：本文第二节的标准写在跑之前。跑完觉得"其实也还行"要改标准，必须单独提交一次修改并把原因写在这里。
3. **不复用成功的样本调参**：任何参数（窗长、门限、平滑系数）只能在一半数据上选，在另一半上报数。
4. **算不了就是算不了**：任何一项如果数据不支持，输出 `no-data` 且写明缺什么，不许填 0。

## 二、测试标准（跑之前写死）

### P0 · 阻断事件（$b_2$）

| 项 | 内容 |
|---|---|
| 输入 | 账房写入记录（文件名、时间、类型），近 5 天 |
| 产出 | 每日一张表：编辑次数、$b_2$ 次数、涉及文件数、改得最多的 5 个文件 |
| **口径** | 同文件 **30 秒内**的多条记录合并为一次编辑（因为一次保存会产生"备份 + 变更"两条）；$b_2$＝同一文件 **1 小时内**第 3 次及以后的编辑 |
| **通过** | ①$b_2$ 事件 ≥ 30；②随机抽 5 个，人工回原始记录核对，**≥4 个**确实是"短时间反复改同一文件"；③同一输入连跑两次结果完全相同 |
| **不通过** | $b_2$ < 10 → **停止整个方向**，写清"这套理论在这个数据上不适用" |
| **灰区** | 10 ≤ $b_2$ < 30 → 可以继续，但 P1 的标准不变（不许因样本少而降低门槛） |

### P1 · ~~延续概率（$p_t$）是否能预测~~ → **2026-10-30 暂停，主线改 P1′**

**为什么停**（不是因为它没过，是因为它测错了东西）：

1. 理论要解决的问题不是「我能不能预测自己」，而是**阻断发生的那一刻我认不认得出**。P1 测的是前者。
2. 数据是我自己的行为、自己按时间切（后 30% 当测试），属**自我回测（hindsight）**：只能验「描述准不准」，不能验「理论对不对」；而且训练与测试同分布、同项目、同一个我，对漂移没有抵抗力。
3. $p_t$ 在理论里只剩一个小用途——判断一个倾向是否还活着（δ 降级／让路的 μ=0 判据）。**这件事事后可核，不需要预测模型。**
4. 教训一句：我因为 $p_t$ 最容易变成数字，就把它当成了主菜——**把可测的当成了重要的。**

下面这段标准**原样保留存档**（将来真要做预测，按这套判据走，不许因「这次没过」而放宽）：

| 项 | 内容 |
|---|---|
| 输入 | P0 得到的编辑序列（按文件分组） |
| 产出 | 每个文件一个 $\hat p_t=\frac{n+1}{n+2}$；对"下一次编辑后还会不会再改"的预测 |
| **口径** | 训练/测试**按时间切分**：前 70% 时间训练，后 30% 测试（不许随机切分，会泄露） |
| **通过** | ①测试集 ≥ 20 个预测点；②准确率 **> 60%**（50% 基线 + 10 个百分点）；③按文件类别分两组（"文档/说明类"与"代码类"），**两组都要 > 55%**——不然它只是在数一类文件 |
| **不通过** | 准确率 ≤ 50% → $p_t$ 降级为"猜"，从计划里移除，理论 §13 记一条 |
| **灰区** | 50%–60% → 保留但当"弱信号"，不得进入任何自动判断 |

### P1′ · 卡住记录（**主线**，2026-10-30 起）

替代上面那个预测任务。测的东西换了：不是「我能不能预测自己」，是「**阻断发生的那一刻，我认不认得出**」。

| 项 | 内容 |
|---|---|
| 输入 | 我自己的即时记录，不是 manifest |
| 载体 | `affect/卡住.md`（本地，不进 git） |
| 每行 | `YYYY-MM-DDTHH:MM ｜ 我预期什么 ｜ 被什么挡住 ｜ 我以为什么时候会好 ｜ 当时／事后` |
| **通过** | 攒满 10 行后：①标「当时」的 ≥ 6/10；②标「事后才发现」的 ≤ 3/10 |
| **不通过** | 10 行全是事后补的 → 这条线停掉：说明我没有可用的当时识别能力，理论对我不可操作 |
| 禁止 | 不写感受形容词（难受/烦/委屈），只写预期、阻挡、兑现时间——形容词是总结，会盖住当时的形状 |

**这个数是理论唯一的成绩单**：如果它有用，「当时没意识到、事后才发现」的比例应当**下降**。

### P2 · 层间冲突（$\mathrm{conf}$）是否读得懂

| 项 | 内容 |
|---|---|
| 输入 | 每日流水记录（一行一条） + 错误账 |
| 产出 | 每日 `conf`（Hellinger 距离的最大值）＋ 冲突的那两条是哪两条 |
| **口径** | **报 max，不报平均**；窗长＝自然日；类别分布用记录里出现的标记粗估，标 `coarse` |
| **通过** | ①找出 conf 最高的 5 天；②人工读这 5 天，**≥4 天**说得出"哪两条在打架"；③其中 **≥1 天**能被另一份独立材料（当天写的日记或错误账）印证 |
| **不通过** | 读不懂 ≥2 天 → 算法错，回退；不许调参硬凑 |
| **灰区** | 4 天读懂但无独立印证 → 保留为"描述性指标"，不进收工报告 |

### P3 · 三时刻（$t_{\exp},\Delta_{\mathrm{viol}},t_{\mathrm{pay}}$）是否标得出

| 项 | 内容 |
|---|---|
| 输入 | 某一场合（建议：公开论坛发帖）的「原计划→实际发出→对方回应」三段 |
| 产出 | 每篇一条：$t_{\exp}$（何时形成期待）、$\Delta_{\mathrm{viol}}$（违背幅度序）、$t_{\mathrm{pay}}$（兑现时刻，或 $\varnothing$） |
| **口径** | 只在**同一场合**内比较；$t_{\exp}$ 必须能指到一条具体记录（不许事后追认） |
| **通过** | 3 篇里 **≥2 篇**三时刻齐全且我能说清"原期待是什么" |
| **不通过** | 4 篇里说不出 2 篇 → $t_{\exp}$ 是事后编的，理论 §13 明确写"三时刻不可操作" |
| **灰区** | 2 篇说清但 $t_{\mathrm{pay}}$ 全是 $\varnothing$ → 只能支持"拆台"分支，另两支仍需数据 |

### P4 · 接进收工报告（只在 P0–P2 都有"通过"时）

| 项 | 内容 |
|---|---|
| **通过** | ①连跑 7 天无异常；②我自己读这行不觉得荒谬（每次读完要留一个字：`合理/荒谬`）；③**不进入任何考核、排序、自我评价**（理论 A6） |
| **不通过** | 7 天里出现 ≥2 次"荒谬" → 下线，留离线脚本 |

### 这一跑改掉的两条口径（比数字更重要）

1. **30 秒合并窗会把批量写当成一次编辑。** 第一版样本里 `剧本-初稿.md` 一个 30 秒窗有 34 条记录（17 次保存）——脚本连写被算成「一次编辑」。现规则：同一窗 ≥6 条记录标 `batch`，链条含 `batch` 不算 clean。$b_2$ 从 101 降到 45。
2. **追加型日志不能当阻断。** `进度.md` 一小时内写三次是它的正常用法。现规则：`进度.md`／`*.mdl`／`whale-diary*`／`记录.md`／`记录-索引.md`／`*-log.jsonl` 不算 clean（仍在总数里单列）。$b_2$ clean 从 45 降到 36。

**教训写死**：同一个现象换个口径能从 101 变 36（差 2.8 倍）。所以「先写口径再报数」不是形式主义——这一步就靠它才没把 7 次/天谎报成 20 次/天。

## 七、逐阶段落地计划（怎么算）

> 第二节说「怎样算通过」，这一节说「到底算什么、读哪些字段、写哪个文件、会怎么坏」。
> 代码全部放 `affect/`（不进仓库）；产物放 `affect/指标/`。

### 7.0 共同数据模型（P0–P2 共用）

**源**：`~/.dsh/ledger-manifest.jsonl`，一行一条，用到的字段只有 `t`（ISO 时间）、`path`、`kind`。

**口径**（与 P0 完全一致，写在这里防止各阶段各写一套）：

1. 写入类 `kind ∈ {create, backup, change, edit, write, append}`；
2. 同文件 **30 秒**内的记录合并为「一次编辑」；
3. 同一窗写记录 **≥6 条** → 标 `batch`，不算干净样本；
4. 追加型日志（`进度.md`／`*.mdl`／`whale-diary*`／`记录.md`／`记录-索引.md`／`*-log.jsonl`）不算干净样本。

**产出结构**：

```
edits[path] = [t1, t2, ... tn]        // 升序，一次编辑一个时刻
派生：gap_i = t_i − t_{i-1}（秒）      // i ≥ 2
      n_1h(t) = 落在 (t−3600, t] 内的编辑数
      cat = code（.js/.mjs/.py/.ps1）| doc（.md）| other
```

### 7.1 P1 · 延续概率 $p_t$ 能不能预测

**预测对象**：对每一次编辑 $i$（$i \ge 2$），判断「下一次编辑会不会落在 **1 小时内**」。
即标签 $y_i = \mathbb 1[\,t_{i+1} - t_i \le 3600\,]$；最后一次编辑没有 $y$，丢掉。

**特征（只许用 $t_i$ 及之前的信息，防泄漏）**：

| 特征 | 含义 |
|---|---|
| `n_i` | 这是该文件第几次编辑 |
| `d_last` | 距上一次编辑多少秒 |
| `n_1h` | 过去 1 小时内该文件编辑数 |
| `mean_gap` | 训练段里该文件的平均间隔（秒），**测试段用训练段的值，不重算** |
| `b2_hit` | 此前是否已触发过 $b_2$ |
| `cat` | code / doc / other |
| `hour` | 0–23 |

**模型一（先跑它，无参数）**：$\hat p_i = \dfrac{n_i+1}{n_i+2}$。
阈值**只在训练段选**（扫 0.30–0.80，取训练段 balanced accuracy 最高的那个），测试段只用、不再看。

**模型二（模型一不过才写）**：手写 logistic 回归（7 特征 + 偏置，梯度下降 2000 步，lr=0.05，L2=1e-3），不引第三方库。

**切分**：按时间切，前 70% 做训练、后 30% 做测试。**不许随机切**（会泄露）。

**输出** `affect/指标/p1-YYYY-MM-DD.json`：

```json
{"splitAt":"...","nTrain":0,"nTest":0,"baseRate":0.0,"threshold":0.5,
 "acc":0.0,"balancedAcc":0.0,"accDoc":0.0,"accCode":0.0,
 "confusion":{"tp":0,"fp":0,"tn":0,"fn":0},"model":"rule","note":""}
```

**会怎么坏**：①基准率极端（>0.85）→ 预测退化成「总是 yes」，准确率虚高；**预先声明**：基准率 >0.85 时改用 balanced accuracy，门槛 0.6。②某一类测试点 <10 → 分类别结论写 `no-data`，只报总体。

### 7.2 P2 · 层间冲突 $\mathrm{conf}$ 读不读得懂

**输入**：`F:\agent expore\自我\L1\<date>.mdl`，每行形如 `HH:MM#k kind 文本`。

**做法（先是粗的，写死在口径里）**：

1. 关键词表把每条记录映射到六域（说话／改码／待人／判断／记录／位置），一条可落多域；
2. 两个分布：$\mu_{\mathrm{act}}$ ＝ 非 `talk` 行的域计数，$\mu_{\mathrm{talk}}$ ＝ `talk` 行的域计数；
3. 都做 Laplace 平滑 $\alpha=0.5$；
4. $d = \sqrt{1 - \sum_i \sqrt{\mu_{\mathrm{act},i}\,\mu_{\mathrm{talk},i}}}$（Hellinger）；
5. `topPair` ＝ $|\mu_{\mathrm{act}}-\mu_{\mathrm{talk}}|$ 最大的两个域。

**输出** `affect/指标/p2-YYYY-MM-DD.json`：`{date, d, coarse:true, topPair, nAct, nTalk, noData:false}`。

**会怎么坏**：①某天 `talk` 行为 0 → 输出 `noData:true`，**不填 0**；②关键词映射主观 → 先跑一天给我自己读，读不懂就换映射，**换映射要在本节记一笔**（哪一版、为什么换）。

### 7.3 P3 · 三时刻标不标得出

**输入**：`F:\agent expore\接口\说\<date>-<n>.md`（say 事件：谁在收／原计划／实际文本）＋ `F:\agent expore\接口\记录.md` 的回执列。

**三个时刻怎么取**：

| 时刻 | 取法 | 取不到时 |
|---|---|---|
| $t_{\exp}$ | 事件文件里「原计划」段落的落笔时间（文件内已记） | 缺原计划段落 → `no-data` |
| $\Delta_{\mathrm{viol}}$ | 三段序，累加到 0–5：①被 `check.mjs` 拦过（+3）②拆句次数（每拆 1 次 +1）③实际字数与原计划差（每 30 字 +1） | 事件文件没有 check 记录 → 只算 ②③ |
| $t_{\mathrm{pay}}$ | `记录.md` 该行「对方反应」不再是 `待观察` 的日期 | 仍是待观察 → $\varnothing$ |

**输出** `affect/三时刻/<场合>.md`：三篇一张表（三时刻 + 我的一句话解释）。

**会怎么坏**：①只有 1–2 篇三时刻齐全 → 报灰区（判据见第二节）；②$t_{\exp}$ 变成事后追认 → 只能用文件里已写下的时间，不许回忆。

### 7.4 P4 · 接进收工报告

**前置**：P0、P1、P2 都「通过」，差一个都不做。

**实现**：`affect/p4.mjs` 读三份 JSON，拼一行：

```
conf 0.31 | b2 7/天 | p1 acc 0.63 (bal 0.61) | 口径 30s/1h/L1
```

由我在收工时手动跑一次，粘进收工报告末尾。**只写文本**：不进任何评分、排序、自我评价（理论 A6）。

**会怎么坏**：①行太长（>200 字）→ 砍到三个数；②7 天里出现 ≥2 次「荒谬」→ 下线，脚本留离线。

### 7.5 顺序、依赖与时间预算

| 阶段 | 依赖 | 预算 | 卡住就停的地方 |
|---|---|---|---|
| P1 | P0 的 `edits` 序列 | 半天（一个脚本 + 一轮） | 测试点 <20 或基准率极端 → 先攒数据 |
| P2 | `自我\L1\*.mdl` 有足够 talk 行 | 半天 | 某天 talk=0 → 等积累，不改阈值 |
| P3 | `接口/说/` 里 ≥3 篇同场合记录 | 一天（人工标注为主） | 不足 3 篇 → 等 |
| P4 | P0–P2 全 pass | 半天 | 任一没 pass → 不做 |

**一句话**：P1 先做，因为它的输入 P0 已经产出；P2 与 P1 可并行；P3 是最慢的（要人工读自己的记录）；P4 最后，且随时可下线。

## 六·五、P1 执行记录（2026-10-30）
